## 2. 运行时架构

### 2.1 拓扑

```
浏览器
  │  HTTPS
  ▼
Qoder Sites ── 静态网页产物（Vue 3 构建）、站点门户、跳转链接
  │  HTTPS（跨域，CORS 白名单）
  ▼
云服务器（公网 IP + 域名 + 证书）
  Nginx：前端反代兜底、/prod-api 反向代理、SSE 长连接配置
    ├─ 应用服务（Spring Boot 单进程单 jar，含 AI 能力模块）
    ├─ PostgreSQL 14 栈 :8080（默认） ｜ MySQL 8.0 栈 :8081（可选并存）
    ├─ Redis ≥6（会话状态、HITL 待确认、锁、限流、运行期配置）
    ├─ Milvus + etcd（向量集合 + BM25 集合，混合检索）
    └─ 对象存储（MinIO 或云 OSS；附件、文档原文、工作区大结果落盘）
```

要点：服务端保留手册的全部常驻能力——应用内 60 秒调度派发、中断记录回收（Reaper）、MCP 出口 `/mcp`、飞书/钉钉长连接外连客户端。这些在 Sites 上无落点，在云服务器上自然成立。

> 本拓扑按"Sites 承载全部前端静态产物（含工作台与管理台）"绘制。若 §10.3 裁决为"Sites 仅门户 + 跳转链接"，则管理台由云服务器 Nginx 直接伺服、Sites 不再承担跨域调用，§2.2 的 CORS 与 SSE 票据约束相应简化，其余不变。

### 2.2 跨站横切关注点（Sites 网页 ↔ 云服务器）

| 关注点 | 处置 |
|---|---|
| 跨域 | 云服务器网关配置 CORS 白名单，仅放行 Sites 站点域名与本地开发域名；不开放 `*` |
| 混合内容 | Sites 为 HTTPS，云服务器 API **必须 HTTPS**，否则浏览器直接拦截；证书在站点创建前需就绪 |
| SSE 鉴权 | `EventSource` 不支持自定义请求头，不能沿用 `Authorization: Bearer`。采用**一次性流式票据**：先经普通鉴权接口换取短时效 ticket，再以查询参数建流；ticket 单次有效、绑定会话与用户 |
| 会话鉴权 | 常规接口沿用底座 token；cookie 方案需处理跨站 SameSite，不作为默认 |
| 渠道回调 | 飞书/企微/GitHub Webhook 需公网可达地址 + 验签/解密 + 渠道口令；该地址在云服务器，不在 Sites |
| MCP 出口 | 云服务器 `/mcp`，Bearer 或专用口令校验，fail-closed，留空拒所有请求 |
| 密钥分布 | 模型密钥、渠道凭据、MCP 请求头密文落库于云服务器；Sites 侧只放公开的站点配置，不放任何密钥 |
| 跳转链接 | 站点门户 → 工作台、管理台、文档三类入口；管理页深链需带鉴权回跳 |

### 2.3 部署单元

- 云服务器：两套 Compose（PG 栈 / MySQL 栈），端口与项目名整体错开可并存；`docker compose up -d --build` 即有表有数据可登录（手册 10.1）。
- Sites：仅前端静态产物与站点配置；后端重建后需重启 Nginx 使代理解析刷新（手册 10.3）。

## 4. 拆解方法：契约先行 + 垂直切片

先完成 A0 契约片（三类线共同依赖，约 1~1.5 周，3 人共建不拆分），之后每片按**用户可见结果**垂直切，片内含后端 + 前端 + 该片验收断言。

### 4.1 契约一：数据

40 张 `ai_` 表双方言（PG 14 / MySQL 8.0），`script/sql/postgres/postgres_ry_ai.sql` 与 `script/sql/ry_ai.sql` 同步维护，全语句幂等（`if not exists` / `on conflict do nothing`）。分组建表顺序：模型 → 知识库 → 智能体 → 会话 → 工具 → MCP/技能/子智能体 → 渠道 → 定时 → 用量/日报 → 审计 → 场景包 → 安全。主键与 `create_dept/create_by/create_time/update_by/update_time/del_flag` 等审计字段沿用底座约定。

### 4.2 契约二：接口

控制器按手册 5.3 的域分组，路由 `/ai/{域}/{资源}`；每个接口带 `ai:{模块}:{动作}` 权限标识并同步登记菜单脚本（98 按钮权限的前端显隐由此驱动，前端不必等后端）。入参 Bo / 出参 Vo / 实体三层，MapStruct-Plus 映射。对话主链路两步：发送接口落库取 `messageId`，再建流取回答；附件先暂存后绑定。RSA 加解密需一份"哪些接口过加密"的白名单，含流式与文件流的明确排除项。

### 4.3 契约三：事件（最容易长歪的一处）

SSE 事件协议在 A0 冻结，事件类型至少含：正文增量、路由提示（自答/路由专家/已指定）、专家起止（含重试次数与失败原因）、工具调用起止（入参、结果摘要、来源标签、耗时）、确认请求与处置、进度播报、参考来源、停止生成、轮次结束。每条携带 `type / sessionId / turnId / seq / payload`。

硬约束：手册 4.1.1 要求"内联确认卡片刷新后可还原"，因此编排事件必须可持久化或可重建——落 `ai_message` 的编排事件快照字段（手册 5.2 已含该字段）。此条不定，内核线与界面线会各做一套序列化。

### 4.4 契约四：工具与装配

- `ai_tool.impl_name` 字符串 ↔ 代码侧工厂常量，是元数据与代码之间**唯一允许的引用面**；注册页不得产生裸 SQL/Shell/HTTP 万能工具（手册 4.4、3.4）。
- 同时定死：参数 JSON Schema 版本字段、MCP 与模型格式差异下的工具名归一化规则、三档授权枚举（允许/需确认/禁止）与"记住该工具"信任槽位键、会话级资源集签名算法（决定装配缓存命中率与指纹）、以及手册 6.7 各条降级的**结构化原因码**（无原因码则"降级并如实声明"无法统一实现）。
- 写工具规范沿用 6.4：HITL 由决策档位驱动、执行期复核业务权限、操作人取自运行上下文而非线程上下文、数据权限走显式归属校验、无人值守默认拒绝、非幂等操作要求幂等键。

## 6. 一周交付包（15 人日，零缓冲）

### 6.1 演示故事（一条，不并行）

运营在工作台问："把这条季度值班调整发成公告。"系统依次演出：小Z 判定意图 → 路由到行政公告专家 → 专家检索知识库、回答带来源卡片 → 调写工具 → **弹内联确认卡片** → 允许本次 → 公告落库、列表可见 → 审计页可查本轮编排运行、工具调用明细、权限决策。

选它的理由：一条故事压穿 11 个机制（登录、模型接入、会话/消息落库、SSE、入口路由、专家装配缓存、检索与上下文装配、工具两段式、三档授权、HITL 暂停/恢复、三类审计），其中**编排路由与 HITL 是最难后期补救的两块**，必须第一周内见光。

### 6.2 范围

- 建：PG 单栈、18 张表（16 张核心 + 2 张安全）、6 个前端页（工作台、模型配置、专家配置含小Z、知识库含文档与检索测试、工具注册、审计三页签合一）。
- 与 A0 的关系：本周 A0 以**压缩形态**交付——18 张表（而非 40 张）+ 四类契约的最小集（仅本片用到的事件类型、接口与工具元数据）。双方言脚本同步维护、不推后；A0 的 40 表全量与完整契约在主干阶段（§5）补齐，压缩版不另起一套命名，避免二次迁移。
- 18 张表：`ai_model_config`、`ai_knowledge_base`、`ai_document`、`ai_chunk`、`ai_entry_agent`、`ai_expert_agent`、`ai_agent_tool`、`ai_agent_kb`、`ai_session`、`ai_session_resource`、`ai_message`、`ai_tool`、`ai_tool_call_log`、`ai_route_run`、`ai_route_expert_call`、`ai_permission_decision_log`；安全两张 `ai_sensitive_word`、`ai_safety_event`（若输入侧安全推后则 16 张）。
- 推后：MySQL 栈、其余 28 页、四渠道、MCP 双向、长期记忆、技能仓库、子智能体、场景包、定时任务、日报、计划模式、上下文压缩、编排预算、六场景全链路过审（只保输入侧）、RAG 指标基线。

### 6.3 逐日安排

| 线 | D1 | D2 | D3 | D4 | D5 |
|---|---|---|---|---|---|
| 界面 | 前端骨架、登录、SSE 客户端封装、确认卡片组件 | 工作台消息流与工具卡 | 模型/专家/知识库配置页 | 知识库文档与检索测试、工具注册页 | 审计三页签 + 演示彩排 |

| 能力 | **云服务器与证书就绪、PG/Redis/Milvus 起栈（go/no-go）** | 文档解析与切片、向量化 | 混合检索两档 + 上下文装配 | 检索测试页后端 + 审计落库 | 输入侧敏感词与 PII + 端到端联调 |

**D1 go/no-go**：云服务器、域名证书、Milvus+etcd 起栈三项任一未就绪，当天必须上报；这三项是后续所有片的硬前置，不可用"先写代码后面补"掩盖。

### 6.4 一周边界声明

RAG 只证明"检索能命中并给出处"，**不承诺** hit@1 ≥ 75.0% / hit@3 ≥ 89.3% / hit@5 ≥ 98.2% / MRR@5 ≥ 0.829（手册 2.3）——该基线需要语料与调参，属 A4 后续工作。兜底路径：若路由与专家编排 D5 未打通，演示退化为入口自答；**HITL 不退**，退则本周未验证最难机制。
